## Задание 4. Реализация RAG-бота

Реализован RAG pipeline:

1. Поиск:
- semantic search по Chroma

2. Генерация:
- LLM через Ollama (llama3 / mistral)

3. Промптинг:
- pre-prompt (ограничение поведения)
- few-shot элементы
- контроль ответа "Я не знаю"

## Задание 5. Выводы

1. RAG-подход показал свою эффективность для построения системы ответов по внутренней базе знаний, так как позволяет использовать актуальные документы без дообучения модели.

2. Качество ответов напрямую зависит от:
   - стратегии разбиения текста на чанки;
   - выбранной embedding-модели;
   - параметров поиска (top_k, пороги релевантности).

3. Использование локальных моделей через Ollama является хорошим решением для MVP:
   - не требует внешнего API;
   - обеспечивает приемлемое качество генерации;
   - позволяет работать с чувствительными данными локально.

4. В ходе тестирования было подтверждено, что RAG-системы уязвимы к атакам типа prompt injection без дополнительной защиты.

5. Реализация защитных механизмов (pre-prompt, фильтрация контекста, контроль ответа) значительно повышает устойчивость системы:
   - вредоносные инструкции не исполняются;
   - утечка данных предотвращается;
   - ответы остаются в рамках заданной логики.

6. Для дальнейшего развития системы (production-уровень) рекомендуется:
   - внедрение гибридного поиска (BM25 + embeddings);
   - использование более мощных embedding-моделей;
   - улучшение фильтрации и ранжирования контекста;
   - добавление мониторинга качества ответов и логирования.

### Общий итог

В рамках проекта был реализован полноценный RAG-бот, включающий:
- сбор и подготовку базы знаний;
- построение векторного индекса;
- реализацию retrieval + generation pipeline;
- защиту от prompt injection атак.

Система корректно отвечает на вопросы по базе знаний, отказывается от генерации при отсутствии информации и демонстрирует устойчивость к вредоносным запросам.
